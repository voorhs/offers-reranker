# Offers Reranker Inference Service

Высокопроизводительный сервис инференса для переранжирования офферов на базе cross-encoder модели с использованием [mosec](https://github.com/mosecorg/mosec).

## Описание

Сервис принимает поисковый запрос пользователя и список офферов, а возвращает офферы отсортированные по релевантности с помощью обученного BERT-like cross-encoder.

## Установка

### Установка зависимостей

```bash
cd inference
uv sync
```

### Установка для разработки

```bash
uv sync --group dev
```

## Конфигурация

Сервис настраивается через переменные окружения с префиксом `RERANKER_`. Можно создать файл `.env` в директории `inference/`:

```bash
# Путь к обученной модели (относительно inference/ директории или абсолютный)
RERANKER_MODEL_PATH=../models/rubert-tiny-reranker

# Размер батча для инференса
RERANKER_BATCH_SIZE=32

# Максимальное количество офферов в одном запросе
RERANKER_MAX_OFFERS=100

# Максимальная длина запроса в символах
RERANKER_MAX_QUERY_LENGTH=512

# Максимальная длина каждого оффера в символах
RERANKER_MAX_OFFER_LENGTH=1000

# Устройство для инференса (auto, cuda, cpu)
RERANKER_DEVICE=auto

# Таймаут mosec в миллисекундах
MOSEC_TIMEOUT=30000
```

### Значения по умолчанию

Если переменные окружения не заданы, используются следующие значения:
- `model_path`: `../models/rubert-tiny-reranker`
- `batch_size`: `32`
- `max_offers`: `100`
- `max_query_length`: `512`
- `max_offer_length`: `1000`
- `device`: `auto` (автоматический выбор CUDA/CPU)

## Запуск сервиса

```bash
cd inference
uv run endpoint.py
```

По умолчанию сервис запускается на `http://localhost:8000`.

## API

### POST /rerank

Переранжировать офферы по релевантности к запросу.

#### Формат запроса

```json
{
  "query": "летнее платье",
  "offers": [
    "Синее летнее платье из хлопка",
    "Зимнее пальто с мехом",
    "Легкое платье с цветочным принтом"
  ],
  "top_k": 2
}
```

**Поля:**
- `query` (string, обязательно): Поисковый запрос пользователя
- `offers` (list[string], обязательно): Список текстовых описаний офферов для переранжирования
- `top_k` (integer, опционально): Вернуть только топ-K наиболее релевантных офферов

#### Формат ответа

```json
{
  "results": [
    {
      "text": "Легкое платье с цветочным принтом",
      "score": 0.9234,
      "rank": 1
    },
    {
      "text": "Синее летнее платье из хлопка",
      "score": 0.8756,
      "rank": 2
    }
  ]
}
```

**Поля:**
- `results` (list): Список офферов отсортированных по убыванию релевантности
  - `text` (string): Оригинальный текст оффера
  - `score` (float): Скор релевантности из модели (0-1, выше = более релевантно)
  - `rank` (integer): Позиция в переранжированном списке (начиная с 1)

#### Валидация

Сервис проверяет:
- Запрос не пустой и не превышает максимальную длину
- Список офферов не пустой и не превышает максимальное количество
- Каждый оффер не пустой и не превышает максимальную длину
- `top_k` (если указан) положительный и не превышает количество офферов

При ошибках валидации возвращается HTTP 400 с описанием ошибки.

## Использование из Python

```python
import msgpack
import requests

# Подготовить запрос
request_data = {
    "query": "летнее платье",
    "offers": [
        "Синее летнее платье",
        "Зимнее пальто",
        "Весенняя куртка"
    ],
    "top_k": 2
}

# Отправить запрос (используем msgpack для сериализации)
response = requests.post(
    "http://localhost:8000/rerank",
    data=msgpack.packb(request_data),
    headers={"Content-Type": "application/msgpack"}
)

# Получить результат
result = msgpack.unpackb(response.content)
for offer in result["results"]:
    print(f"Rank {offer['rank']}: {offer['text']} (score: {offer['score']:.4f})")
```
